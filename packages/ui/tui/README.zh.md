# `@deepseek-ai/dsh-tui`

[English](README.md) | 中文

全屏终端前门。它在备用屏幕中渲染一个活跃 agent 的会话并接管终端输入；agent 生命周期、会话持久化、工具执行以及面向模型的提问工具仍是独立的组合条目。

该插件要求 stdin 与 stdout 都是 TTY，否则在挂载时抛错，而不是退化为行式输出：静默回退会掩盖部署错误并改变交互语义。管道与自动化请使用[一次性 headless 应用](../../bundle/headless/README.md)、[ACP](../../acp/acp/README.md) 或 [JSON-RPC](../../sdk/server/README.md)。

随产品发布的组合是 [`dsh-tui-app`](../../bundle/tui-app/README.md)，即 `dsh` 与 `dsh --profile tui` 背后的 bundle。

## 配置

| 键 | 默认值 | 含义 |
|---|---|---|
| `session` | 必填 | 该终端驱动的 agent 的确切 `SessionId`，由宿主创建时给出。 |
| `agentWaitTimeoutMs` | `30000` | 等待该 agent 的最长时间；超时会在普通终端拒绝启动。 |
| `color` | `true` | 是否输出 SGR 序列；`false` 以相同布局无样式渲染。 |
| `colorDepth` | `auto` | 绘制所用的色彩深度：`auto` 读取终端声明的能力，`truecolor`、`256`、`16` 或 `none` 可钉住退化阶梯的某一级。`color` 为 `false` 时忽略。 |
| `headLines` | `8` | 折叠工具卡片正文时保留的开头行数。 |
| `tailLines` | `4` | 折叠工具卡片正文时保留的结尾行数。 |
| `showReasoning` | `false` | 推理内容初始是否可见；终端控制键可随时切换。 |
| `maxSuggestions` | `8` | `/`、`@` 与模型选择菜单在滚动前显示的候选行数；小终端会显示得更少。 |
| `images` | `true` | 是否尝试内联渲染图片；`false` 时无论终端能力如何，都始终绘制图片的文本兜底。 |
| `imageMaxWidthCells` | `60` | 内联图片在终端列数上的最大宽度。 |
| `imageMaxHeightCells` | — | 内联图片在终端行数上的最大高度；不设置则保持图片自身的宽高比。 |
| `task` | — | 屏幕就绪后提交的首个提示，用于 `dsh "<task>"`。 |

插件会在 `agentWaitTimeoutMs` 限制内等待携带 `session` 的 agent，并且只在该 agent 存在之后才进入全屏模式。因此，缺失的 agent 会在普通终端上成为启动拒绝，而不是无限等待或藏在备用屏幕后面的诊断。它在该 agent 上安装 [`installModelSelection`](../../core/agent/README.md)，用于填充 persona 的 `{{provider}}`/`{{model}}` 变量并路由每次请求。

## 它绘制什么

新会话以一个冷启动头部开场，它作为对话记录的首个条目被注入，因此在第一个回合之后随对话滚走，绝不重绘或钉住：DeepSeek 鲸鱼图形与产品名称和版本并排，连同路由、权限预设、折叠了主目录的工作目录，以及一行按键提示。该图形在真彩色或 256 色深度下绘制；窄于 78 列的终端把它叠放在身份信息之上，而低于 60 列或高度不足以容纳整块的终端则以单行身份头部取代它。恢复的会话保留自己的首个条目，不显示头部。

对话记录由**追加来源的会话日志**折叠而成，而非来自模型可见表面，因此恢复的会话保留读者已经看过的每条消息，被压缩的区间也仍可读地留在其标记之后。它渲染带 `›` 标记的人类回合与带彩色 `◆` 标记的助手回合、以 Markdown 呈现的助手文本、推理内容（默认隐藏）、工具卡片，以及回合结束、命令结算和压缩的单行提示；每个人类或助手回合之前都空出一行，使回合边界以间距呈现，而编辑器边框保留唯一的水平线。渲染结果按条目缓存，仅在内容或宽度变化时失效，因此重绘长对话只花费真正变动的条目。

工具卡片来自每个工具自己的 `presentCall`/`presentResult`（[渲染意图](../../core/tools/README.md)）：terminal、diff、read、search 与 web 卡片各有终端形态，本渲染器不认识的卡片形态回退到面向模型的结果。工具改变它在这里的呈现方式靠改自己的 presenter，而不是在本包中加分支。卡片以调用行开场——presenter 的标题，否则是带一个可识别参数的 `name(args)`——结算后的结果以 `╰` 肘线挂在它下方、正文变暗，调用失败时肘线着错误色；卡片周围没有边框。

读者附加的图片会内联绘制，走的是 pi-tui 自己的 `Image` 组件：它的 `getCapabilities()` 探测从当前终端自身的环境（而非某个部署设置）决定协议（Kitty 或 iTerm2 graphics），既不支持两者的终端 —— 普通 xterm、没有 Kitty 透传的大多数 `tmux`/`screen` 会话、或丢失了该协议 `TERM` 的 SSH 跳转 —— 会绘制与 pi-tui 在其他地方一致的文本兜底（已知时给出媒体类型、像素尺寸与文件名）。有能力的终端读取实际字节的动作走 `ctx.attachments`，在渲染路径之外进行：条目立即从持久引用自身的元数据绘制兜底文本，只有等后台读取完成后才替换，因此附件存储缓慢或失败会退化为兜底而不是阻塞屏幕。`images: false` 会完全跳过本包的读取，无论终端实际能力如何都始终把每张图片绘制为兜底 —— 这是给代理或录制流水线这类不应收到图形转义的固定部署选择的；pi-tui 自己那次有缓存、无副作用的能力探测仍会在其 `Image` 组件内部执行。因为图片位于可滚动的对话记录中而非固定高度的浮层里，它不会像输入触发菜单与模型选择器那样在行数不足时整体隐藏：pi-tui 自身的滚动记账会在视口边缘裁剪已放置的 Kitty 图片，与裁剪一段很长的工具卡片或助手消息完全一样，因此五行高的终端上一张二十行高的图片会滚动进入视野而不是消失。`imageMaxWidthCells`/`imageMaxHeightCells` 限定单次放置能请求的最大尺寸。目前只有读者自己附加的图片会这样绘制 —— 该方式尚未覆盖的前向兼容区块见”已知限制”。

底栏报告运行状态——回合运行时是一个旋转指示器，空闲时是一枚绿点，位于耗时与 token 数之前——请求实际使用的路由（来自最新的 `request/context`，`/model` 在请求之前切换时会立即重述）、来自 [`ctx.tokenMeter`](../../llm/token-meter/README.md) 的上下文占用、最新的 `todo/write` 计划、收件箱排队深度、当前有效的控制键，以及当组合挂载它们时的常驻会话状态指示器：当前目标（已完成的目标除外）、激活或待处理的计划模式，以及有效的权限预设。它不钉住任何常驻按键提示：中断提示挂在运行中的回合上，其余由输入行承载。

编辑器的输入行以 `›` 提示标记开场；输入为空时以一枚暗色占位符说明读者可以做什么，一旦开始输入或打开菜单，留白收窄为标记本身，在窄到无法让编辑器在其旁保持可用的终端上则完全隐去。

在光标下方，编辑器基于 pi-tui 的自动补全提供两个输入触发菜单：在输入开头键入 `/` 会列出活跃 [`ctx.commands`](../../interaction/commands/README.md) 注册表为该 agent 解析的全部命令，以及活跃 [`ctx.skills`](../../skill/skill/README.md) 目录为它提供的可由用户调用的技能 —— 屏幕启动后注册的命令或技能会在下一次击键时出现；在词边界键入 `@` 会列出本会话**正在运行的子 agent**，与 Web 端 `@` 来源读取的是同一份名册（`ctx.subagents.listChildren`，过滤到运行中；子 agent 的名字依次取其持久会话标题、创建标签、原始 id）。未组合 subagent 能力时 `@` 不提供任何候选；未组合技能能力时 `/` 只列出命令。模型目录未收录的技能在其描述中标记 `user-only`。两者都绘制在编辑器块内，每行一个候选及其描述，并且在小终端上都让位于其他内容：菜单会收敛到页脚、编辑器与一行对话记录之外剩余的行数，连一行候选都放不下的终端干脆不显示菜单 —— 触发键保持无效，而不是从一个看不见的列表里选择。选中的 `/` 候选补全为 `/name ` 行；注册表能解析的命令经注册表提交，其余名字 —— 即技能 —— 作为普通提示文本原样送达模型，由 [`dsh-tool-skill`](../../skill/tool-skill/README.md) 的 pre-step 边界注入渲染后的技能正文应答，与 Web 端的纯文本拾取一致。选中的 `@` 候选把引用 `@name ` 插入输入框，同样原样送达。

`/model` 无需重启即可切换本会话请求使用的路由。候选来自活跃的 [`ctx.llm`](../../llm/llm/README.md) 适配器注册表 —— 与 Web 宿主以 `session.models` 下发的是同一来源，因此两个界面不会对“存在哪些模型”产生分歧 —— 展平为每行一个路由，提供方列举失败以不可选的诊断行呈现。不带参数时它在对话之上打开一个键盘面板：带编号的行、当前路由带标记、方向键或数字选择、`enter` 应用、`esc` 撤销且不取消运行中的回合、不清空排队的提示。带参数时直接选择（`/model deepseek-v4-pro`，或当模型 id 对应多个提供方时写 `provider/model`），没有任何适配器公布该 id 时会大声失败并列出可选路由。

每条路由的推理强度来自其适配器的声明，随目录一并读取，因此未声明强度的路由在任何地方都不提供强度选择：在其行上按 `→` 保持在列表不动，任何强度参数都会大声失败并指名该路由。在声明了强度的行上按 `→` 打开该路由的强度层 —— 模型默认值加上每个已声明的强度，即将生效的强度带标记 —— `enter` 应用带标记行，数字直接应用对应行，`esc` 返回模型列表且光标保持不变；强度层是同一个面板的一个状态，因此撤销它不可能关掉列表。`/model <route> <effort>` 直接固定一个已公布的强度，`/model <route> default` 改为请求适配器默认值；未知强度在拾取时被拒绝并列出可选项，绝不会拖到请求时。

选中的路由经其适配器校验并在下一个提示组装边界生效 —— 正在运行的步骤保留其已组装的配置；当排队或已记录的内容携带图片时，声明不接受图片输入的模型会在拾取时被拒绝，与 Web 端的防护一致。不带强度的模型拾取遵循 Web composer 的强度规则：重新拾取当前路由保留其强度，切换路由则采用新模型的默认值，且切换提示指名被替换的强度（`was <effort>`），因为存储的默认值无法区分显式强度与物化强度。`default` 拾取不安装任何强度，因此每次请求解析适配器的实时默认值，持久化的配置节会清除已存储的强度。拾取同时经 [`ctx.agentDefaultModel`](../../core/agent-default-model/README.md) 持久化为部署默认值，保存失败作为警告附在切换提示上，而不是让拾取失败。已安装的选择在每次读取时解析 —— 先是本进程内的拾取，其次会话日志的最后一个请求头（因此 `--resume` 会恢复切换过的路由），再次是启动固定值或部署默认值。连一行候选都放不下的终端上面板让位，并给出直接选择形式的提示。

## 启动选择器

`pickResumeSession` 是不带会话名的 `dsh --resume` 在本前门接管屏幕之前打开的键盘列表，让读者无需知道 id 就能继续一个已持久化的会话。调用方（已发布 bundle 中的 [`tui-startup`](../../bundle/tui-app/README.md)）已确认两个流都是 TTY，并将它们传入。名册来自 `resumeCandidates(headers)`：子 agent 会话被丢弃（委派草稿不是对话），最新的会话排在最前，id 用于打破创建时间并列。每行携带创建时间、折叠了主目录前缀的工作目录和截断的会话 id，每个片段都经过 `displayLine()`，因为持久化的元数据不受信任。`↑`/`↓` 移动，数字直接选中该行（前九行），`enter` 恢复光标所在行，`esc` 与 `ctrl+c` 都在不恢复也不新建任何东西的情况下退出 —— 启动时没有会丢失的排队工作，而被放弃的选择器绝不能用新会话顶替调用所要求的恢复。列表原位重绘，在选择器结束时擦除，并把 stdin 留在行模式，使随后进入的屏幕从干净的终端开始；中止调用方的信号也以同样方式结束它，因此原始模式 stdin 不会比树活得更久。放不下一个候选行的终端不会得到列表 —— 既不渲染也不捕获按键 —— 调用方会拒绝启动并指出显式形式。

## 终端所有权

到达 pi-tui 或窗格标题的每个字符串都先经过 `displayText()`：它折叠回车、展开制表符，并把其他所有 C0/DEL/C1 控制字符渲染为可见的 `\xNN` 转义。只有本包与 pi-tui 会产生 ANSI 控制序列，因此不受信任的工具输出或模型文本无法重绘屏幕、移动光标或设置窗格标题。内联图片是本包唯一把原始字节而非 `displayText()` 规整过的文本交给 pi-tui 的地方 —— pi-tui 的 `Image` 组件自己把它们 base64 编码进图形协议的放置序列，因此攻击者无法通过图片字节夹带转义序列：该编码只接纳像素数据，不接纳任意控制字节。

调色板按角色键控，并在部署所支持的最深色彩深度下绘制：`COLORTERM` 声明时使用真彩色，`TERM` 标明时使用 256 色，其余情况使用 16 色 ANSI 集，再往下则无色彩；`colorDepth` 可钉住某一级阶梯。每一级都保留角色的含义——失败在全部级别上都显示为错误色——并且正文与背景保持终端默认值，因此宿主终端的浅色或深色主题会重映射界面；选中态在每一级上都使用反显。本包没有自己的主题设置（[依据](../../../.agents/notes/proposed/architecture/2026-08-26-tui-color-depth-ladder.md)）。

## 控制键

| 按键 | 效果 |
|---|---|
| `enter` | 提交：已解析的斜杠命令经 [`ctx.commands`](../../interaction/commands/README.md) 执行；其余内容送达 agent —— 空闲时开启后续回合，运行中作为 steering。 |
| `esc` | 关闭打开的菜单或选择面板 —— 运行中的回合与排队的提示都保留；两者都没有打开时取消正在运行的回合。 |
| `ctrl+c` | 取消正在运行的回合；无可取消时离开会话。 |
| `ctrl+r` | 显示或隐藏推理内容。 |
| `ctrl+o` | 展开或折叠所有工具卡片正文。 |
| `/` | 在输入开头打开命令与技能菜单；继续输入字母可收窄。选中的命令经注册表执行；选中的技能作为提示文本提交，由 pre-step 边界应答。 |
| `@` | 在词边界打开运行中子 agent 菜单；继续输入字母可收窄。 |
| `up` / `down` | 移动打开菜单或选择面板中的选中项。 |
| `tab` | 补全选中的候选并继续输入。 |
| `/exit`、`/quit` | 离开：取消任何回合，等待 agent 静默以便会话落盘，然后退出。 |
| `/help` | 列出活跃注册表为该 agent 解析的全部命令。 |
| `/model` | 打开模型选择面板；在声明了强度的路由上按 `→` 打开其强度层，`esc` 返回列表。`/model <provider/model> [<effort>|default]` 直接切换，未知的 id 或强度会列出可选项。 |

## 交互

插件注册唯一的 `ctx.userQuestions` 提供者，并**仅为自己的 agent** 应答 `approval/request`，其他 agent 的提问交由调用链的其余部分处理。两者都表现为对话之上的同一个键盘面板：带编号的选项、方向键或数字选择、`space` 切换多选、`tab` 改为输入自由文本、`enter` 作答、`esc` 撤销。被撤销或被收回的审批结算为 `cancelled`，所有调用方对此都按拒绝处理。

## Model Experience

间接：`/model` 命令写入本前门安装的模型选择引用；选中的路由经其适配器校验，提示组装在下一个组装边界快照该选择 —— 模型与强度一起 —— 因此正在运行的步骤保留其已组装的配置，消费新选择的请求头将其持久化（请求头携带推理强度；强度变化没有单独的会话事件）。同一次拾取还会持久化为部署默认值，因此后续会话从选中的路由与强度启动。

#### KV Cache effect

安装的模型选择保持固定，直到 `/model` 或组合方改变它。会话中途切换 —— 模型或推理强度 —— 改变请求前缀运行所依赖的字段，后续请求的提供方侧缓存复用可能减少或失效；提示内容本身不受影响，与 Web 端完全一致。

## Known Limitations and Deferred Work

- **一个终端一个 agent** —— 插件驱动 `session` 指定的单个会话；终端内没有会话切换器，第二次挂载会争抢同一块屏幕。
- **启动选择器没有收窄** —— 它按最新在前列出全部顶层持久会话，没有过滤或搜索；数字可达前九行，其余靠方向键，会话很多的读者需要滚动。
- **直接选择限定在已公布目录内** —— `/model <id>` 只接受活跃目录公布的路由；未列入目录但仍在服务的模型只能通过启动时的 `--model`/`--provider` 达成。
- **流式粒度取决于日志** —— 对话记录跟随 `assistant/chunk` 事件，因此不记录 chunk 的组合会在每步消息提交时才绘制该步文本。
- **只有读者自己附加的图片会内联绘制** —— 助手或工具结果中的图片块（`read_image` 工具的结果、前向兼容的助手输出）仍然不绘制图片；`ImageBlock` 本身与角色无关，但目前没有适配器产生助手图片，`read_image` 的卡片是没有图片渲染能力的 `generic`，所以两者在有当下的生产者需要之前都保持纯文本。
- **没有针对多路复用器或 SSH 的专门探测** —— 能力探测是 pi-tui 的 `getCapabilities()` 对当前进程环境的一次性读取；一台具备 Kitty 能力的本地终端如果是经由不转发该协议 `TERM` 的多路复用器或远程跳转到达的，会和真正不支持的终端一样回退，没有单独的远程感知启发式。
- **触发符只在词首生效** —— `/` 只在首行开头打开菜单，`@` 只在词边界打开；行中的 `/`、标点后的 `@`、以及后续行上的任何触发符都不打开菜单。该检测属于 pi-tui 的编辑器，改动它意味着 fork 编辑器。
- **提示留白位于编辑器旁侧而非其内部** —— pi-tui 的编辑器不提供占位符或提示前缀钩子，因此 `›` 标记与空输入占位符绘制在边框旁的留白里，占位符让位于输入时边框会重排一次；要在输入区内呈现幽灵文本，需要改动 pi-tui 本身。
- **`@` 查询是单个词** —— 空格会结束词元，因此输入时名字含空格的子 agent 只能按其第一个词匹配；拾取的引用仍携带完整名字。
- **菜单是扁平列表** —— Web 端按来源分组并带小标题；终端把命令与技能列在同一份名册里，命令在前、没有分组标题。
- **`@` 引用是纯文本** —— 拾取插入 `@name ` 并原样送达模型；终端没有引用编解码器或附件块，agent 对 `@` 的消费是未来的业务工作（Web 端同样推迟了它）。
- **没有文件补全** —— 任何触发符或 `tab` 都不提供工作区文件路径。Web 端同样没有文件补全来源；在任一端新增它都是一项独立决策。
