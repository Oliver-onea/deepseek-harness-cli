# `@deepseek-ai/dsh-tui`

[English](README.md) | 中文

全屏终端前门。它在备用屏幕中渲染一个活跃 agent 的会话并接管终端输入；agent 生命周期、会话持久化、工具执行以及面向模型的提问工具仍是独立的组合条目。

该插件要求 stdin 与 stdout 都是 TTY，否则在挂载时抛错，而不是退化为行式输出：静默回退会掩盖部署错误并改变交互语义。管道与自动化请使用[一次性 headless 应用](../../bundle/headless/README.md)、[ACP](../../acp/acp/README.md) 或 [JSON-RPC](../../sdk/server/README.md)。

随产品发布的组合是 [`dsh-tui-app`](../../bundle/tui-app/README.md)，即 `dsh` 与 `dsh --profile tui` 背后的 bundle。

## 配置

| 键 | 默认值 | 含义 |
|---|---|---|
| `session` | 必填 | 该终端驱动的 agent 的确切 `SessionId`，由宿主创建时给出。 |
| `agentWaitTimeoutMs` | `30000` | 等待该 agent 的最长时间；超时会在普通终端拒绝启动。 |
| `color` | `true` | 是否输出 SGR 序列；`false` 以相同布局无样式渲染。 |
| `headLines` | `8` | 折叠工具卡片正文时保留的开头行数。 |
| `tailLines` | `4` | 折叠工具卡片正文时保留的结尾行数。 |
| `showReasoning` | `false` | 推理内容初始是否可见；终端控制键可随时切换。 |
| `maxSuggestions` | `8` | `/`、`@` 与模型选择菜单在滚动前显示的候选行数；小终端会显示得更少。 |
| `task` | — | 屏幕就绪后提交的首个提示，用于 `dsh "<task>"`。 |

插件会在 `agentWaitTimeoutMs` 限制内等待携带 `session` 的 agent，并且只在该 agent 存在之后才进入全屏模式。因此，缺失的 agent 会在普通终端上成为启动拒绝，而不是无限等待或藏在备用屏幕后面的诊断。它在该 agent 上安装 [`installModelSelection`](../../core/agent/README.md)，用于填充 persona 的 `{{provider}}`/`{{model}}` 变量并路由每次请求。

## 它绘制什么

对话记录由**追加来源的会话日志**折叠而成，而非来自模型可见表面，因此恢复的会话保留读者已经看过的每条消息，被压缩的区间也仍可读地留在其标记之后。它渲染人类回合、以 Markdown 呈现的助手文本、推理内容（默认隐藏）、工具卡片，以及回合结束、命令结算和压缩的单行提示。渲染结果按条目缓存，仅在内容或宽度变化时失效，因此重绘长对话只花费真正变动的条目。

工具卡片来自每个工具自己的 `presentCall`/`presentResult`（[渲染意图](../../core/tools/README.md)）：terminal、diff、read、search 与 web 卡片各有终端形态，本渲染器不认识的卡片形态回退到面向模型的结果。工具改变它在这里的呈现方式靠改自己的 presenter，而不是在本包中加分支。

底栏报告运行状态、请求实际使用的路由（来自最新的 `request/context`，`/model` 在请求之前切换时会立即重述）、来自 [`ctx.tokenMeter`](../../llm/token-meter/README.md) 的上下文占用、最新的 `todo/write` 计划、收件箱排队深度、当前有效的控制键，以及当组合挂载它们时的常驻会话状态指示器：当前目标（已完成的目标除外）、激活或待处理的计划模式，以及有效的权限预设。

在光标下方，编辑器基于 pi-tui 的自动补全提供两个输入触发菜单：在输入开头键入 `/` 会列出活跃 [`ctx.commands`](../../interaction/commands/README.md) 注册表为该 agent 解析的全部命令，以及活跃 [`ctx.skills`](../../skill/skill/README.md) 目录为它提供的可由用户调用的技能 —— 屏幕启动后注册的命令或技能会在下一次击键时出现；在词边界键入 `@` 会列出本会话**正在运行的子 agent**，与 Web 端 `@` 来源读取的是同一份名册（`ctx.subagents.listChildren`，过滤到运行中；子 agent 的名字依次取其持久会话标题、创建标签、原始 id）。未组合 subagent 能力时 `@` 不提供任何候选；未组合技能能力时 `/` 只列出命令。模型目录未收录的技能在其描述中标记 `user-only`。两者都绘制在编辑器块内，每行一个候选及其描述，并且在小终端上都让位于其他内容：菜单会收敛到页脚、编辑器与一行对话记录之外剩余的行数，连一行候选都放不下的终端干脆不显示菜单 —— 触发键保持无效，而不是从一个看不见的列表里选择。选中的 `/` 候选补全为 `/name ` 行；注册表能解析的命令经注册表提交，其余名字 —— 即技能 —— 作为普通提示文本原样送达模型，由 [`dsh-tool-skill`](../../skill/tool-skill/README.md) 的 pre-step 边界注入渲染后的技能正文应答，与 Web 端的纯文本拾取一致。选中的 `@` 候选把引用 `@name ` 插入输入框，同样原样送达。

`/model` 无需重启即可切换本会话请求使用的路由。候选来自活跃的 [`ctx.llm`](../../llm/llm/README.md) 适配器注册表 —— 与 Web 宿主以 `session.models` 下发的是同一来源，因此两个界面不会对“存在哪些模型”产生分歧 —— 展平为每行一个路由，提供方列举失败以不可选的诊断行呈现。不带参数时它在对话之上打开一个键盘面板：带编号的行、当前路由带标记、方向键或数字选择、`enter` 应用、`esc` 撤销且不取消运行中的回合、不清空排队的提示。带参数时直接选择（`/model deepseek-v4-pro`，或当模型 id 对应多个提供方时写 `provider/model`），没有任何适配器公布该 id 时会大声失败并列出可选路由。选中的路由经其适配器校验，与 Web 端 `/model` 入口完全一致地应用该模型的默认推理强度，并在下一个提示组装边界生效 —— 正在运行的步骤保留其已组装的路由；当排队或已记录的内容携带图片时，声明不接受图片输入的模型会在拾取时被拒绝，与 Web 端的防护一致。拾取同时经 [`ctx.agentDefaultModel`](../../core/agent-default-model/README.md) 持久化为部署默认值，保存失败作为警告附在切换提示上，而不是让拾取失败。已安装的选择在每次读取时解析 —— 先是本进程内的拾取，其次会话日志的最后一个请求头（因此 `--resume` 会恢复切换过的路由），再次是启动固定值或部署默认值。连一行候选都放不下的终端上面板让位，并给出直接选择形式的提示。

## 终端所有权

到达 pi-tui 或窗格标题的每个字符串都先经过 `displayText()`：它折叠回车、展开制表符，并把其他所有 C0/DEL/C1 控制字符渲染为可见的 `\xNN` 转义。只有本包与 pi-tui 会产生 ANSI 控制序列，因此不受信任的工具输出或模型文本无法重绘屏幕、移动光标或设置窗格标题。

调色板只使用标准 16 色 ANSI 前景色与 SGR 属性，正文与背景保持终端默认值，因此宿主终端的浅色或深色主题会重映射整个界面；选中态使用反显。本包没有自己的主题设置。

## 控制键

| 按键 | 效果 |
|---|---|
| `enter` | 提交：已解析的斜杠命令经 [`ctx.commands`](../../interaction/commands/README.md) 执行；其余内容送达 agent —— 空闲时开启后续回合，运行中作为 steering。 |
| `esc` | 关闭打开的菜单或选择面板 —— 运行中的回合与排队的提示都保留；两者都没有打开时取消正在运行的回合。 |
| `ctrl+c` | 取消正在运行的回合；无可取消时离开会话。 |
| `ctrl+r` | 显示或隐藏推理内容。 |
| `ctrl+o` | 展开或折叠所有工具卡片正文。 |
| `/` | 在输入开头打开命令与技能菜单；继续输入字母可收窄。选中的命令经注册表执行；选中的技能作为提示文本提交，由 pre-step 边界应答。 |
| `@` | 在词边界打开运行中子 agent 菜单；继续输入字母可收窄。 |
| `up` / `down` | 移动打开菜单或选择面板中的选中项。 |
| `tab` | 补全选中的候选并继续输入。 |
| `/exit`、`/quit` | 离开：取消任何回合，等待 agent 静默以便会话落盘，然后退出。 |
| `/help` | 列出活跃注册表为该 agent 解析的全部命令；页脚提示即指向它。 |
| `/model` | 打开模型选择面板；`/model <provider/model>` 直接切换，未知 id 会列出可选路由。 |

## 交互

插件注册唯一的 `ctx.userQuestions` 提供者，并**仅为自己的 agent** 应答 `approval/request`，其他 agent 的提问交由调用链的其余部分处理。两者都表现为对话之上的同一个键盘面板：带编号的选项、方向键或数字选择、`space` 切换多选、`tab` 改为输入自由文本、`enter` 作答、`esc` 撤销。被撤销或被收回的审批结算为 `cancelled`，所有调用方对此都按拒绝处理。

## Model Experience

间接：`/model` 命令写入本前门安装的模型选择引用；选中的路由经其适配器校验并应用该模型的默认推理强度，提示组装在下一个组装边界快照该选择，因此正在运行的步骤保留其已组装的路由，消费新路由的请求头将其持久化。同一次拾取还会持久化为部署默认值，因此后续会话从选中的路由启动。

#### KV Cache effect

安装的模型选择保持固定，直到 `/model` 或组合方改变它。会话中途切换改变了请求前缀运行的路由，后续请求的提供方侧缓存复用可能减少或失效；提示内容本身不受影响，与 Web 端完全一致。

## Known Limitations and Deferred Work

- **一个终端一个 agent** —— 插件驱动 `session` 指定的单个会话；终端内没有会话切换器，第二次挂载会争抢同一块屏幕。
- **没有推理强度选择** —— `/model` 应用所选模型的默认推理强度，不提供强度菜单；Web composer 的两级 Model/Effort 拾取在终端没有对应物。
- **直接选择限定在已公布目录内** —— `/model <id>` 只接受活跃目录公布的路由；未列入目录但仍在服务的模型只能通过启动时的 `--model`/`--provider` 达成。
- **流式粒度取决于日志** —— 对话记录跟随 `assistant/chunk` 事件，因此不记录 chunk 的组合会在每步消息提交时才绘制该步文本。
- **不渲染图片** —— pi-tui 可在支持的终端中内联放置图片，但附件块目前不产生任何终端输出。
- **触发符只在词首生效** —— `/` 只在首行开头打开菜单，`@` 只在词边界打开；行中的 `/`、标点后的 `@`、以及后续行上的任何触发符都不打开菜单。该检测属于 pi-tui 的编辑器，改动它意味着 fork 编辑器。
- **`@` 查询是单个词** —— 空格会结束词元，因此输入时名字含空格的子 agent 只能按其第一个词匹配；拾取的引用仍携带完整名字。
- **菜单是扁平列表** —— Web 端按来源分组并带小标题；终端把命令与技能列在同一份名册里，命令在前、没有分组标题。
- **`@` 引用是纯文本** —— 拾取插入 `@name ` 并原样送达模型；终端没有引用编解码器或附件块，agent 对 `@` 的消费是未来的业务工作（Web 端同样推迟了它）。
- **没有文件补全** —— 任何触发符或 `tab` 都不提供工作区文件路径。Web 端同样没有文件补全来源；在任一端新增它都是一项独立决策。
