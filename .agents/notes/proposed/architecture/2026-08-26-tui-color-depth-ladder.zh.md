# Agent Note: TUI color depth ladder replaces the 16-color-only palette

Status: proposed

[English](2026-08-26-tui-color-depth-ladder.md) | 中文

## Problem

`dsh-tui` 曾以文档形式确立了一条调色板立场：只使用标准 16 色 ANSI 前景色与 SGR 属性，正文文字与背景保持终端默认值，不提供主题设置。这一立场是有意为之的。它换来了宿主主题重映射——浅色或深色终端会通过自身调色板重新着色整个界面，对比度完全由读者已有的选择决定——也带来了单色安全性：任何能运行该产品的终端都能完整呈现每种运行状态的含义；同时没有任何主题配置面。

这一立场的代价是产品完全没有视觉识别度。每个角色颜色都是宿主终端所定义的"青色"或"蓝色"；DeepSeek 品牌色（`#4D6BFE`）在任何地方都不出现；本应体现产品身份的界面元素——冷启动头部、鲸鱼图形、回合标记——读起来与普通终端输出毫无区别。冷启动画面仅凭观感就被判定为不可接受，而视觉身份如今已成为明确声明的优先事项。pi-tui 无需任何额外支持即可渲染真彩色，因此限制始终是这条立场本身，而非框架。

## Proposal

保持调色板按角色键控、语义化——`dim`、`bold`、`user`、`tool`、`accent`、`success`、`warn`、`error`、`removed`、`added`、`code`、`selected`——并在部署所支持的最深色彩深度下绘制每个角色。阶梯依次为：

1. **真彩色**：当 `COLORTERM` 为 `truecolor` 或 `24bit` 时，角色直接携带品牌调色板（`tool`/`accent` 使用 `#4D6BFE`）。
2. **256 色**：当 `TERM` 标明 256 色时，使用最接近的 xterm-256 近似色。
3. **16 色**：其余所有情况，使用旧立场所用的 ANSI 前景色。
4. **无色彩**：当 `color` 关闭时，样式函数为恒等映射，布局完全一致。

经验证的 `colorDepth` 配置字段（`auto`、`truecolor`、`256`、`16`、`none`；默认 `auto`）可为环境误报的部署钉住某一级阶梯，使色彩深度成为部署层面的决策，而不仅仅是一次探测。

阶梯以如下保证取代旧立场：

- **角色含义在每一级阶梯上都成立。**失败在全部四级上都显示为错误色，成功显示为成功色；退化的只有色相，含义从不丢失。
- **宿主主题对比度依然成立。**每一级阶梯上正文文字与背景都保持终端默认值；选中态保持反显，因此它会反转宿主正在使用的任何配色。
- **单色安全性依然成立。** `color: false` 渲染完全相同的布局、不带任何样式，与之前一致。
- **`displayText()` 继续净化每一个不可信字符串**——模型文本、工具输出、文件名、会话标题、技能与命令标签；只有包自身编写的界面元素是可信的字面源码。此规则不受本次立场反转的影响。

## Alternatives considered

**保留 16 色专属立场。**它仍能换来它一贯能换来的一切，但产品如今对视觉身份的需要，已经超过了对最后那一点宿主主题重映射能力的需要。阶梯结构把旧调色板保留为第三级，因此这一反转并未放弃旧立场为 16 色终端换来的任何东西——放弃的只是"在终端允许更深色彩时拒绝使用"这一点。

**仅真彩色、不做退化。**要求真彩色的 TUI 会把 ssh 会话、旧 `TERM` 值下的 tmux，以及任何止步于 256 色或 16 色的终端排除在外。退化是阶梯中让单色安全性承诺继续生效的部分；不带退化就发布，等于提出比它所取代的旧立场更严格的要求。

**用户可选的主题设置。**调色板选择器是没有人要求过的配置面；角色机制已经把审美决策集中在一个模块里，而且深度是终端能力，不是用户偏好。`colorDepth` 用于在环境损坏时覆盖探测结果；它并不开放主题选择。

**为界面元素与面板使用背景色。**给背景着色会让所触及的区域失去宿主主题重映射能力，并可能在调色板从未测试过的终端上产生不可读的组合。仅前景着色、背景保持默认，守住对比度保证；选中态出于同样原因保持反显。

## Acceptance criteria

- `packages/ui/tui/src/theme.ts` 在真彩色、256 色、16 色与无色彩四级上构建角色调色板，并有测试断言每一级的 SGR 序列与探测顺序。
- 插件验证 `colorDepth`，并在一处将其与 `COLORTERM`/`TERM` 一并解析。
- `packages/ui/tui/README.md` 及其中文对应文档以阶梯描述取代 16 色专属立场，Config 表列出 `colorDepth`。
- 冷启动头部与鲸鱼图形消费该阶梯：在真彩色/256 色下绘制，在 16 色/无色彩下由单行身份头部替代。

## Risks

真彩色与 256 色的色相是按深色终端（常见情形）挑选的；在浅色宿主上，部分中间色调可能显得比预期更淡。仅前景着色、默认背景与反显选中态限制了损害范围，`colorDepth: none` 仍是逃生通道。探测可能误读奇异的 `TERM`；钉住的覆盖值正是为此而设——这正是它作为配置而非代码存在的原因。
