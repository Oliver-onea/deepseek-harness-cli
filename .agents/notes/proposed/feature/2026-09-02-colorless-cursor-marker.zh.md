# Agent Note: 游標列以形狀標記，而不只靠顏色

Status: proposed

[English](2026-09-02-colorless-cursor-marker.md) | 中文

## 問題

在 `--no-color` 下，以及在無色階修好之後的 `colorDepth: none` 下，`/model` 選擇器與問題面板把每一列畫得一模一樣。沒有任何東西指出 `enter` 會套用到哪一列，讀者只能猜，或者退出。

兩處都以 `palette.selected(row)` 標示游標列，而 `createPalette(false).selected` 是恆等函式——這是刻意的，也有一個既有測試如此斷言。承載游標的只有反白，而無色階沒有反白可給。`/` 命令選單不受影響：pi-tui 的自動完成即使關掉顏色也會自己發出 `\x1b[7m`。

由終端的第二輪對抗性審查發現，它稱這是剩下最嚴重的使用者可見問題，並拒絕自行修復，理由是這屬於維護者的設計判斷，而非明確的缺陷。

## 提案

以行首欄位的 `▸` 標明游標列，並在有顏色之處繼續由 `palette.selected` 上樣式。

`theme.ts` 中的 `cursorRow(row, isCursor, palette)` 是決定此事的唯一位置，取代了 `model-picker.ts`（兩處）與 `questions.ts` 中重複的同一段三元運算式。各列現在以兩欄的間槽開頭，因此標記佔有自己的一欄，而不會緊貼數字；它替換第一欄而不是加寬該列，呼叫端對面板寬度的 `slice` 依然成立。

結果是：有顏色之處為冗餘編碼，無顏色之處由形狀獨撐。

```
--no-color   "▸ 2.   deepseek-official/deepseek-v4-pro"
truecolor    "\x1b[7m▸ 2.   deepseek-official/deepseek-v4-pro\x1b[27m"
```

人必須讀取的狀態，絕不應只倚賴顏色；這是本次遵循的通則，而無色階只是它的缺席變得可見之處。

## 曾考慮的替代方案

**讓 `palette.selected` 在每一階（含無色階）都發出反白。** 只需一行，而且確實修好了選擇器。否決的理由是它與 README 對 `color: false` 的承諾相矛盾——「renders the same layout unstyled」——而反白就是一種樣式。它同時也會推翻一個刻意斷言恆等函式的既有測試。

**接受現狀，並把限制寫進文件。** 誠實且免費。否決的理由是受影響的介面正是讀者挑選模型的地方；一個游標看不見的選單，與其說是限制，不如說是不能用的選單。

**只給無色階加標記。** 讓其他每一階的位元組維持不變。否決的理由是同一個元件有兩套渲染規則會逐漸走樣，而且這個標記在有顏色時也是一項改善——一眼掃過去，形狀比一塊反白讀得更快。

## 驗收標準

1. 關掉顏色時，`/model` 與問題面板的游標列可分辨。
2. 有顏色時，同一列同時帶有反白與標記。
3. 由單一 helper 為三個呼叫點決定此事。
4. 標記不改變列寬。

## 風險

- **兩欄間槽讓每一列右移一欄**，在窄寬度下少一欄內容。各列本來就會截斷到面板寬度，因此損失的是最長模型名稱的一個字元。
