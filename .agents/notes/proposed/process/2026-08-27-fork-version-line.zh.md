# Agent Note: 本 fork 自有的版本線

Status: proposed

[English](2026-08-27-fork-version-line.md) | 中文

## 問題

本倉庫是 DeepSeek Harness 的 fork，帶著約兩萬行上游沒有的改動，而在此之前它與被它分叉的產品無從區分。

- 它的 224 份 manifest 全部寫著 `0.1.0-rc.5`，也就是分叉出來的那個上游 commit 的版本。上游之後已經發布了 `0.1.0-rc.6`、`rc.7`、`rc.8`、`0.1.1-rc.1` 與 `0.1.1-rc.2`，因此這個 fork 的號碼**落在一條仍在推進的上游版本線內部**，描述的卻是上游從未有過的樹。
- 冷啟動標題與 `dsh --version` 都宣告 `DeepSeek Harness v0.1.0-rc.5`。讀者無法分辨手上的本機建置與已發布的產品，而根據此建置提出的錯誤回報會被歸到上游的版本上。
- 這些套件命名為 `@deepseek-ai/*`，該 scope 在 npm 上的維護者是 `imccyu` 與 `tianyicui-deepseek`。`pnpm release:publish` 會嘗試把 224 個套件發布進別人的命名空間。

倉庫裡也沒有任何 tag，因此沒有任何東西記錄這個 fork 是從上游何處離開的。

## 提案

**這個 fork 保有自己的語意化版本線，身分由名稱承載，而不是由數字承載。**

1. **版本。** 一條從 `0.2.0` 起算的獨立版本線。號碼描述的是**這個 fork 裡**改了什麼：新功能是 minor，修錯是 patch，破壞相容是 major。從 `0.2.0` 起算同時讓整條線離開上游仍在推進的 `0.1.x`，因此這個 fork 印出的任何號碼都不會被誤認為某個上游發布。
2. **同步升版。** 224 個成員與工作區根一起移動，這正是 `scripts/release/bump.ts` 對 `dsh` family 既有的規定。此處不作改變。
3. **身分。** 標題與 `--version` 宣告 `DeepSeek Harness (fork)`。告訴讀者他在跑什麼的是這個標記，不是那串數字。
4. **上游基準。** 以 tag `upstream/<版本>` 標記 fork 離開的那個 commit —— `upstream/0.1.0-rc.5` 位於 `47f943859b`。於是 `git log upstream/0.1.0-rc.5..master` 就是「這個 fork 加了什麼」的精確答案，而下一次合併上游時再加一個這樣的 tag。
5. **發布 tag。** `dsh-v<版本>`，即 `bump.ts` 已經印出的形式。
6. **發布。** 什麼都不發。該 scope 屬於上游，而這份建置是以 symlink 把 `apps/cli/lib/bin.js` 掛上 `PATH` 來安裝的。

## 曾考慮的替代方案

**跟隨上游號碼並加上 fork 後綴，例如 `0.1.1-rc.2+oliver.3`。** 因一項機制事實而否決：SemVer 在比較時**忽略 build metadata**，因此兩個不同的 fork 建置會被判定為相等，讀者無法分辨何者較新。改把標記放進 prerelease 欄位（`0.1.1-rc.2.oliver.3`）雖可正確排序，但上游每發一次版就得替 fork 重新編號，而 fork 自己的改動反而得不到任何遞增。

**日期版本，例如 `2026.8.27`。** 永不撞號且必然遞增，這點確實有吸引力。否決的理由是 224 個套件透過範圍運算子互相依賴；`^` 在一條日期線上沒有意義，而發布工具鏈是以 `major`/`minor`/`patch` 推理的。

**保留 `0.1.0-rc.5`，只改名稱。** 最便宜，而名稱確實承載了身分。否決的理由是那個號碼仍然佔著上游現行版本線裡的一個位置，且下一次從上游合併之後，「這是哪一個 0.1.0-rc.5」將無法回答。

**把 scope 改成作者擁有的名稱。** 正確，而且一旦要發布任何東西就是必須的。延後：那是 224 份 manifest 加上每一處內部依賴、import 路徑與 `cordis.yml` 引用，而這份建置是以 symlink 安裝、發布於無處。標題上的標記已經補上了今天真正會咬人的那道身分落差。

## 驗收標準

1. 根與全部 224 個成員都讀作 `0.2.0`。
2. 標題與 `--version` 標明此建置為 fork。
3. `upstream/0.1.0-rc.5` 標記分叉點，且 `git log upstream/0.1.0-rc.5..master` 只列出本 fork 的工作。
4. 發布以 `dsh-v0.2.0` 標記。
5. 不向 npm 發布任何東西。

## 風險

- **scope 仍然是上游的。** 目前防止誤觸 `release:publish` 的屏障只是沒有人去跑它；誤觸會在登錄伺服器端因權限而失敗，不會造成損害，但不應把它當成唯一屏障。改名仍然是真正的解法，也是一旦要對外散布時的第一項工作。
- **`(fork)` 讓標題第一行寬了七欄。** lockup 版面在 78 欄以下會退化為單行標題，而單行本來就會截斷，因此存活下來的正是這個標記。
